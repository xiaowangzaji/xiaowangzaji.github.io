一、操作系统基本概念与功能

1.1 什么是操作系统

操作系统（OS） 是管理计算机硬件与软件资源的系统软件，是用户与硬件之间的接口。

1.2 OS 的四大功能

功能管理对象核心任务
处理器管理进程/线程进程调度、同步、通信
存储管理内存分配/回收、地址映射、虚拟内存
设备管理I/O 设备驱动管理、缓冲、分配、调度
文件管理文件/目录存储空间管理、目录管理、保护

1.3 操作系统分类

  • 批处理系统：多道批处理（内存中同时驻留多道程序）
  • 分时系统：时间片轮转，用户交互式使用（如 UNIX）
  • 实时系统：严格时限要求（航空控制、工业控制）
  • 通用操作系统：Windows、Linux、macOS

1.4 内核态 vs 用户态

维度内核态（Kernel Mode）用户态（User Mode）
权限最高权限，可执行所有指令受限权限
访问范围全部内存和设备仅用户空间
切换方式中断、异常、系统调用通过系统调用陷入内核
目的保护系统安全，防止用户程序破坏系统隔离用户程序

二、进程与线程

2.1 基本概念

概念说明
程序存储在磁盘上的可执行文件（静态）
进程程序的一次执行实例，是资源分配的基本单位（动态）
线程进程内的执行单元，是 CPU 调度的基本单位

2.2 进程 vs 线程

对比维度进程线程
资源拥有独立的地址空间、文件描述符等共享进程的内存和资源
开销创建/切换开销大创建/切换开销小
通信方式IPC（管道、消息队列、共享内存等）直接读写共享变量
独立性一个进程崩溃不影响其他进程一个线程崩溃可能导致整个进程崩溃
并发性多进程并发多线程并发
粒度粗粒度细粒度

2.3 进程的组成

进程控制块（PCB）+ 程序段（代码）+ 数据段（数据）

PCB 包含：进程 ID、状态、优先级、寄存器上下文、内存指针、打开文件列表、记账信息等。

三、进程状态转换

3.1 五状态模型

            创建
             │
             ▼
    ┌─── 就绪（Ready）──────┐
    │       │  ▲            │
    │       ▼  │ 调度       │
    │    运行（Running）     │
    │       │               │
    │       ▼ I/O请求       │
    │   阻塞（Blocked）──────┘ I/O完成
    │       │
    │       ▼
    │    终止（Terminated）
    └─── 超时/时间片用完

状态说明：

状态说明
创建进程正在被创建，分配资源中
就绪已获得除 CPU 外所有资源，等待调度
运行正在 CPU 上执行
阻塞等待某个事件（如 I/O 完成、信号量）
终止进程执行完毕或被强制结束

3.2 挂起状态（七状态模型）

当内存不足时，OS 可将进程换出到磁盘（挂起）：

  • 就绪挂起：在磁盘上，一旦调入内存即可运行
  • 阻塞挂起：在磁盘上，且等待某事件

四、进程调度算法

4.1 调度层次

高级调度（作业调度）→ 中级调度（内存调度/对换）→ 低级调度（进程调度/CPU调度）

4.2 调度算法对比

算法策略优点缺点适用场景
先来先服务（FCFS）按到达顺序简单公平短作业等待长批处理
短作业优先（SJF）预计运行时间最短优先平均等待时间最短长作业可能饥饿，需预知运行时间批处理
时间片轮转（RR）固定时间片轮流执行公平，响应快时间片过小开销大分时系统
优先级调度按优先级高低灵活低优先级饥饿实时系统
多级反馈队列（MLFQ）多个优先级队列 + 时间片递增综合最优复杂通用 OS

4.3 多级反馈队列（MLFQ）详解

队列1（时间片=1）→ 队列2（时间片=2）→ 队列3（时间片=4）→ ...
       ↑ 未完成降一级                              │
       └───────────────────────────────────────────┘

规则：

  1. 新进程进入最高优先级队列（队列 1）
  2. 队列 1 中未完成的进程降到队列 2，以此类推
  3. 时间片逐级翻倍（1, 2, 4, 8, ...）
  4. 高优先级队列有任务时不服务低优先级队列
  5. 同一队列内按 FCFS

效果：短作业在高层快速完成，长作业在底层执行，兼顾响应时间和吞吐量。

4.4 调度指标

指标公式含义
周转时间完成时间 - 到达时间从提交到完成的总时间
带权周转时间周转时间 / 运行时间反映相对等待
等待时间周转时间 - 运行时间在就绪队列等待的时间
响应时间首次产生响应的时间 - 提交时间交互式系统关注

五、进程同步与互斥

5.1 临界区与互斥

临界区：访问临界资源（一次仅允许一个进程使用的资源）的代码段。

互斥的四个条件：

  1. 空闲让进：无进程在临界区时，应允许一个请求进入
  2. 忙则等待：已有进程在临界区时，其他进程必须等待
  3. 有限等待：等待进入的进程应在有限时间内进入
  4. 让权等待：不能进入时应释放 CPU（不忙等）

5.2 信号量与 PV 操作

信号量（Semaphore）：整型变量 + 两个原子操作

// P 操作（wait/申请）
P(S) {
    S--;
    if (S < 0) {  // 资源不足
        阻塞当前进程;
        插入等待队列;
    }
}

// V 操作（signal/释放）
V(S) {
    S++;
    if (S <= 0) {  // 有进程在等待
        唤醒一个等待进程;
    }
}
信号量值含义
S > 0可用资源数量
S = 0资源刚好分配完，无等待
S < 0

互斥信号量：初始值为 1。

5.3 管程（Monitor）

管程是高级同步机制，将共享数据和操作封装在一起：

  • 一次只有一个进程可以在管程内执行
  • 条件变量（Condition Variable）用于等待和唤醒
  • 比信号量更安全（编译器保证互斥）

六、经典同步问题

6.1 生产者-消费者问题

semaphore mutex = 1;    // 互斥访问缓冲区
semaphore empty = n;    // 空缓冲区数量
semaphore full = 0;     // 满缓冲区数量

// 生产者
void producer() {
    while (true) {
        生产一个产品;
        P(empty);    // 等待空位
        P(mutex);    // 互斥访问
        放入缓冲区;
        V(mutex);
        V(full);     // 增加满位
    }
}

// 消费者
void consumer() {
    while (true) {
        P(full);     // 等待产品
        P(mutex);    // 互斥访问
        取出产品;
        V(mutex);
        V(empty);    // 增加空位
        消费产品;
    }
}

⚠️ P 操作顺序很重要：必须先 P 资源信号量（empty/full），再 P 互斥信号量（mutex），否则可能死锁。

6.2 读者-写者问题

semaphore rw_mutex = 1;  // 读写互斥
semaphore mutex = 1;     // 保护 read_count
int read_count = 0;      // 读者数量

// 读者（读者优先）
void reader() {
    while (true) {
        P(mutex);
        read_count++;
        if (read_count == 1) P(rw_mutex);  // 第一个读者锁定
        V(mutex);

        读数据;

        P(mutex);
        read_count--;
        if (read_count == 0) V(rw_mutex);  // 最后一个读者释放
        V(mutex);
    }
}

// 写者
void writer() {
    while (true) {
        P(rw_mutex);  // 写者独占
        写数据;
        V(rw_mutex);
    }
}

6.3 哲学家进餐问题

semaphore chopstick[5] = {1, 1, 1, 1, 1};

void philosopher(int i) {
    while (true) {
        思考;
        P(chopstick[i]);              // 拿左边筷子
        P(chopstick[(i + 1) % 5]);   // 拿右边筷子
        进餐;
        V(chopstick[i]);              // 放左边
        V(chopstick[(i + 1) % 5]);   // 放右边
    }
}

死锁问题：五个哲学家同时拿起左边筷子 → 全部等待右边 → 死锁。

解决方案：

  1. 最多允许 4 个哲学家同时进餐
  2. 奇数号哲学家先拿左再拿右，偶数号反之
  3. 仅当左右筷子都可用时才拿起（AND 信号量）

七、死锁

7.1 死锁的四个必要条件

条件说明
互斥资源一次只能被一个进程使用
占有并等待进程已占有资源，还在等待其他资源
不可抢占资源不能被强制剥夺
循环等待形成环路等待链

7.2 死锁预防

破坏四个必要条件之一：

方法破坏的条件代价
资源一次性分配占有并等待资源利用率低
可剥夺资源不可抢占实现复杂
资源有序分配循环等待需定义全局顺序

7.3 死锁避免——银行家算法

安全状态：存在一个安全序列，使得所有进程都能按序完成。

银行家算法流程：
1. 进程请求资源
2. 试探性分配
3. 执行安全性检查（寻找安全序列）
4. 若安全 → 真实分配；若不安全 → 拒绝，进程等待

数据结构：

  • Available：可用资源向量
  • Max：最大需求矩阵
  • Allocation：已分配矩阵
  • Need = Max - Allocation：尚需矩阵

7.4 死锁检测与解除

检测：使用资源分配图，存在环路则可能死锁（单实例资源，环路 = 死锁）。

解除：

  1. 资源剥夺：抢占资源
  2. 撤销进程：终止一个或多个死锁进程
  3. 进程回退：回滚到之前的安全状态

八、内存管理

8.1 内存分配方式

方式说明问题
连续分配给进程分配连续的内存空间外部碎片
单一连续分配内存分为系统区和用户区，用户区只给一个进程严重浪费
固定分区预先划分多个固定大小的分区内部碎片
动态分区按需动态划分外部碎片

8.2 动态分区分配算法

算法策略特点
首次适应（FF）从头找第一个足够大的空闲区简单，低地址碎片多
最佳适应（BF）找最小的足够大的空闲区节省大空间，但产生极小碎片
最坏适应（WF）找最大的空闲区减少小碎片，但大空间被破坏
邻近适应（NF）从上次找到的位置继续分散碎片

8.3 分页存储管理

基本思想：将逻辑地址空间和物理内存都划分为固定大小的页/页框。

逻辑地址 = 页号 + 页内偏移
物理地址 = 页框号 + 页内偏移
┌─────────────┐
│   页号 P     │  页内偏移 W  │  ← 逻辑地址
└──────┬──────┘
       │ 查页表
       ▼
┌─────────────┐
│   页框号 F   │  页内偏移 W  │  ← 物理地址
└─────────────┘

特点：无外部碎片，有内部碎片（最后一页可能不满）。

8.4 分段存储管理

按逻辑模块分段（代码段、数据段、堆栈段），每段长度不一。

逻辑地址 = 段号 + 段内偏移

特点：方便共享和保护，有外部碎片。

8.5 段页式存储管理

先分段，段内再分页。结合两者的优点，是多数现代 OS 的方式。

九、虚拟内存

9.1 基本概念

虚拟内存：逻辑上扩充内存容量，使程序认为拥有连续的地址空间，实际可能分布在物理内存和磁盘上。

局部性原理：

  • 时间局部性：被访问的指令/数据很快可能再次被访问（如循环变量）
  • 空间局部性：被访问的指令/数据附近的指令/数据很快被访问（如数组遍历）

9.2 请求分页

按需调入页面，不一次性加载整个进程：

访问页面 → 页表查询 → 有效位 = 1 → 物理内存访问
                       → 有效位 = 0 → 缺页中断 → 调入页面 → 更新页表 → 重试

9.3 页表与 TLB

页表：页号 → 页框号的映射表，存储在内存中。

问题：每次内存访问需要两次访存（查页表 + 实际访问），性能下降一半。

TLB（Translation Lookaside Buffer）：快表，页表的高速缓存。

访问流程：
1. 查 TLB → 命中 → 得到页框号 → 访问内存（极快）
2. TLB 未命中 → 查页表 → 更新 TLB → 访问内存

9.4 页面置换算法

当内存满了需要调入新页时，选择淘汰哪一页：

算法策略特点
OPT（最佳）淘汰最长时间后才会被访问的页面理论最优，不可实现（需预知未来）
FIFO淘汰最早进入的页面简单，但可能产生 Belady 异常（页框增加反而缺页率增加）
LRU（最近最少使用）淘汰最久未被访问的页面接近 OPT，需要硬件支持
Clock（时钟/NRU）访问位 + 修改位，循环扫描LRU 的近似，实用

Clock 算法：

页面有 2 个标志位：
- 访问位（A）：被访问过 = 1
- 修改位（M）：被修改过 = 1

扫描策略（4 轮）：
1. 找 A=0, M=0 → 淘汰（最优选择，既未访问也未修改）
2. 找 A=0, M=1 → 淘汰，并清 A 位（修改过但未访问）
3. 如果还没找到，所有页 A 位清零，回到第 1 轮

9.5 缺页中断与抖动

缺页中断：访问的页面不在内存中，触发中断请求 OS 调入。

抖动（Thrashing）：页面频繁换入换出，CPU 利用率急剧下降。

原因：分配的页框数太少，进程刚调入就被淘汰。

解决：

  • 工作集策略：保证进程有足够的页框容纳其工作集
  • 页面置换频率控制：缺页率过高时增加页框分配

十、文件系统

10.1 文件控制块（FCB）

FCB 是文件元信息的集合，包含：

  • 文件名、物理地址、逻辑结构、物理结构
  • 访问权限、创建/修改时间、文件大小
  • 在 UNIX 中称为 inode

10.2 目录结构

结构说明特点
一级目录所有文件在一张表中简单，不支持共享和重名
二级目录用户目录 + 文件目录支持用户隔离
树形目录多级目录树最常用，支持共享和层次管理
图结构目录目录可共享（硬链接）支持共享，可能有环

10.3 磁盘调度算法

算法策略特点
FCFS先来先服务公平但效率低
SSTF（最短寻道时间优先）选择离当前磁头最近的请求效率高，但可能产生饥饿
SCAN（电梯算法）单向扫描到底再反向避免饥饿，较公平
C-SCAN（循环扫描）单向扫描到底后直接回到起点更均匀的等待时间
磁道请求序列: 55, 58, 39, 18, 90, 160, 150, 38, 184
当前磁头: 100，方向向内（减小）

SCAN:  100 → 90 → 58 → 55 → 39 → 38 → 18 → 150 → 160 → 184
C-SCAN: 100 → 90 → 58 → 55 → 39 → 38 → 18 → 184 → 160 → 150

十一、I/O 管理

11.1 I/O 控制方式

方式CPU 参与程度特点
程序控制（轮询）CPU 不断查询设备状态简单但 CPU 浪费严重（忙等待）
中断驱动设备就绪后发中断通知 CPUCPU 可并行处理其他任务
DMADMA 控制器负责数据传输，仅在开始和结束时中断 CPU适合大批量数据传输
通道控制I/O 处理器独立执行 I/O 指令CPU 完全不参与 I/O

11.2 缓冲区管理

  • 单缓冲：一个缓冲区交替使用
  • 双缓冲：一个输入一个输出，可并行
  • 循环缓冲：多个缓冲区组成环
  • 缓冲池：OS 管理的缓冲区集合

11.3 假脱机技术（SPOOLing）

将独占设备改造为共享设备：

  • 输入井：磁盘上模拟输入设备
  • 输出井：磁盘上模拟输出设备
  • 典型应用：打印 spooling

12.2 权限管理

# 文件权限

chmod u+x file            # 用户可执行

12.3 查找与过滤

# 查找文件

# 文本搜索
grep "error" logfile             # 搜索包含 error 的行
grep -r "error" /path            # 递归搜索
grep -i "error" logfile          # 忽略大小写
grep -v "debug" logfile          # 排除包含 debug 的行
grep -n "error" logfile          # 显示行号
grep -c "error" logfile          # 计数

# 管道组合
ps aux | grep nginx | grep -v grep  # 查找 nginx 进程
cat logfile | grep "ERROR" | wc -l  # 统计 ERROR 行数
cat access.log | awk '{print $1}' | sort | uniq -c | sort -rn | head -10  # 访问 Top 10 IP

十三、常见面试要点速记

1. 进程 vs 线程 vs 协程：
   - 进程：资源分配单位，独立地址空间
   - 线程：调度单位，共享进程资源
   - 协程：用户态轻量线程，由程序调度而非 OS

2. 死锁四个必要条件：互斥、占有并等待、不可抢占、循环等待
   预防：破坏其中之一即可

3. 页面置换算法：
   - OPT（理论最优）> LRU（实用最佳）> Clock（LRU 近似）> FIFO
   - Belady 异常：FIFO 可能出现

4. 虚拟内存的作用：
   - 逻辑上扩充内存
   - 进程隔离（每个进程独立地址空间）
   - 按需加载，提高内存利用率

5. Linux 查看 CPU/内存占用最高的进程：
   - top（按 P 排序 CPU，按 M 排序内存）
   - ps aux --sort=-%cpu | head
   - ps aux --sort=-%mem | head
