适配器模式

约 1528 字大约 5 分钟

2025-09-24

定义

适配器模式将一个类的接口转换成客户期望的另一个接口，使原本由于接口不兼容而不能一起工作的类可以协同工作。它就像现实世界中的电源转接头，让不同规格的插头能够插入插座。

结构

  • Target（目标接口）：客户端所期望的接口规范，定义了客户端使用的操作。
  • Adaptee（适配者）：需要被适配的已有类，其接口与目标接口不兼容。
  • Adapter（适配器）：核心角色，实现目标接口并持有适配者实例，在两者之间进行转换。
  • Client（客户端）：通过目标接口与适配器交互，无需感知适配者的存在。

适配器模式有两种实现方式：类适配器（通过多重继承）和对象适配器（通过组合）。对象适配器更为常用，因为它遵循组合优于继承的原则，且更灵活。

UML 类图（文本描述）

Client --> Target（依赖）
Target <|-- Adapter（实现/继承）
Adapter --> Adaptee（组合/关联）
  • Adapter 实现 Target 接口
  • Adapter 内部持有 Adaptee 的引用
  • 客户端面向 Target 编程，实际调用的是 Adapter，Adapter 再委托给 Adaptee

代码实现（C++ 示例）

#include <iostream>
#include <string>

// ========== 目标接口 ==========
class ITarget {
public:
    virtual ~ITarget() = default;
    virtual std::string request() const = 0;
};

// ========== 适配者（已有类，接口不兼容） ==========
class Adaptee {
public:
    std::string specificRequest() const {
        return "Adaptee: 这是特殊请求的响应";
    }
};

// ========== 对象适配器 ==========
class Adapter : public ITarget {
private:
    Adaptee* adaptee_;
public:
    explicit Adapter(Adaptee* adaptee) : adaptee_(adaptee) {}

    std::string request() const override {
        // 将目标接口调用转换为适配者的接口调用
        std::string result = adaptee_->specificRequest();
        // 可以在这里做额外的转换处理
        return "[Adapter 转换] " + result;
    }
};

// ========== 类适配器（使用多重继承） ==========
class ClassAdapter : public ITarget, private Adaptee {
public:
    std::string request() const override {
        return "[类适配器] " + Adaptee::specificRequest();
    }
};

// ========== 实际应用：媒体播放器 ==========
class IMediaPlayer {
public:
    virtual ~IMediaPlayer() = default;
    virtual void play(const std::string& audioType, const std::string& fileName) = 0;
};

class Mp3Player {
public:
    void playMp3(const std::string& fileName) {
        std::cout << "Playing mp3 file: " << fileName << std::endl;
    }
};

class AdvancedMediaPlayer {
public:
    void playVlc(const std::string& fileName) {
        std::cout << "Playing vlc file: " << fileName << std::endl;
    }
    void playMp4(const std::string& fileName) {
        std::cout << "Playing mp4 file: " << fileName << std::endl;
    }
};

class MediaAdapter : public IMediaPlayer {
private:
    AdvancedMediaPlayer advancedPlayer_;
    std::string audioType_;
public:
    explicit MediaAdapter(const std::string& audioType) : audioType_(audioType) {}

    void play(const std::string& audioType, const std::string& fileName) override {
        if (audioType == "vlc") {
            advancedPlayer_.playVlc(fileName);
        } else if (audioType == "mp4") {
            advancedPlayer_.playMp4(fileName);
        }
    }
};

class AudioPlayer : public IMediaPlayer {
private:
    MediaAdapter* mediaAdapter_ = nullptr;
public:
    ~AudioPlayer() { delete mediaAdapter_; }

    void play(const std::string& audioType, const std::string& fileName) override {
        if (audioType == "mp3") {
            std::cout << "Playing mp3 file: " << fileName << std::endl;
        } else if (audioType == "vlc" || audioType == "mp4") {
            mediaAdapter_ = new MediaAdapter(audioType);
            mediaAdapter_->play(audioType, fileName);
        } else {
            std::cout << "Invalid media type: " << audioType << std::endl;
        }
    }
};

int main() {
    // 基础适配器示例
    Adaptee adaptee;
    Adapter adapter(&adaptee);
    std::cout << adapter.request() << std::endl;

    // 媒体播放器示例
    AudioPlayer player;
    player.play("mp3", "song.mp3");
    player.play("vlc", "movie.vlc");
    player.play("mp4", "video.mp4");

    return 0;
}

代码实现（Python 示例）

from abc import ABC, abstractmethod


# ========== 目标接口 ==========
class ITarget(ABC):
    @abstractmethod
    def request(self) -> str:
        pass


# ========== 适配者 ==========
class Adaptee:
    def specific_request(self) -> str:
        return "Adaptee: 这是特殊请求的响应"


# ========== 对象适配器 ==========
class Adapter(ITarget):
    def __init__(self, adaptee: Adaptee) -> None:
        self._adaptee = adaptee

    def request(self) -> str:
        result = self._adaptee.specific_request()
        return f"[Adapter 转换] {result}"


# ========== 实际应用：支付系统适配 ==========
class PaymentProcessor(ABC):
    @abstractmethod
    def pay(self, amount: float, currency: str) -> bool:
        pass


# 旧版支付网关（接口不兼容）
class LegacyPayGateway:
    def do_payment(self, amount_cents: int, currency_code: str) -> int:
        """返回状态码: 0=成功, 1=失败"""
        print(f"LegacyPayGateway: 处理 {amount_cents} {currency_code} 分")
        return 0  # 假设成功


# 新版支付网关（接口不兼容）
class NewPaymentGateway:
    def process(self, amount: float, cur: str, method: str = "credit_card") -> dict:
        print(f"NewPaymentGateway: 处理 {amount} {cur} 通过 {method}")
        return {"status": "success", "tx_id": "TX123456"}


class LegacyGatewayAdapter(PaymentProcessor):
    """将旧版支付网关适配到新的 PaymentProcessor 接口"""

    def __init__(self, gateway: LegacyPayGateway) -> None:
        self._gateway = gateway

    def pay(self, amount: float, currency: str) -> bool:
        amount_cents = int(amount * 100)
        status = self._gateway.do_payment(amount_cents, currency.upper())
        return status == 0


class NewGatewayAdapter(PaymentProcessor):
    """将新版支付网关适配到新的 PaymentProcessor 接口"""

    def __init__(self, gateway: NewPaymentGateway) -> None:
        self._gateway = gateway

    def pay(self, amount: float, currency: str) -> bool:
        result = self._gateway.process(amount, currency.upper())
        return result["status"] == "success"


class CheckoutService:
    """客户端：面向 PaymentProcessor 接口编程"""

    def process_checkout(self, processor: PaymentProcessor, amount: float) -> None:
        success = processor.pay(amount, "CNY")
        if success:
            print("✓ 支付成功！")
        else:
            print("✗ 支付失败！")


if __name__ == "__main__":
    # 基础适配器
    adaptee = Adaptee()
    adapter = Adapter(adaptee)
    print(adapter.request())

    # 支付系统适配
    checkout = CheckoutService()

    legacy_adapter = LegacyGatewayAdapter(LegacyPayGateway())
    checkout.process_checkout(legacy_adapter, 99.90)

    new_adapter = NewGatewayAdapter(NewPaymentGateway())
    checkout.process_checkout(new_adapter, 199.00)

适用场景

  • 需要使用已有类但其接口与当前系统不匹配时
  • 需要将多个不同接口的组件统一为一致的接口时
  • 系统集成或迁移阶段，需要兼容新旧系统
  • 使用第三方库时，其 API 与项目现有接口风格不一致

优点

  • 单一职责原则：将接口转换逻辑与业务逻辑分离
  • 开闭原则：新增适配器无需修改现有客户端代码
  • 复用性好：可以在不修改适配者代码的前提下复用已有类
  • 灵活性高：对象适配器方式可以随时替换适配者实例

缺点

  • 系统复杂度增加：引入额外的适配层，增加理解成本
  • 性能损耗：多了一层间接调用（通常可忽略不计）
  • 过度使用：如果大量使用适配器，系统可能变得碎片化

与其他模式的关系

  • 适配器 vs 桥接模式：适配器用于让已有接口协同工作（事后补救），桥接模式用于事前设计两个独立维度的接口（预先规划）
  • 适配器 vs 装饰器模式：适配器改变接口，装饰器不改变接口只增强功能
  • 适配器 vs 外观模式：适配器转换接口，外观模式简化接口
  • 适配器 vs 代理模式：适配器改变接口类型，代理保持相同接口但控制访问

实际应用

  • C++ STL：std::queue 和 std::stack 本质上是容器适配器，将底层 deque/vector 适配为队列/栈接口
  • Python：collections.abc 中的各种适配器类，如 Iterable、Sequence 等抽象基类
  • Java：java.util.Arrays.asList() 将数组适配为 List 接口
  • Spring Framework：HandlerAdapter 将不同类型的 Controller 适配为统一的请求处理接口
  • 日志框架：SLF4J 作为日志门面，通过适配器兼容 Logback、Log4j 等不同日志实现
