装饰器模式

约 1497 字大约 5 分钟

2025-09-24

定义

装饰器模式允许在不修改原有对象结构的前提下，动态地给对象添加新的功能。它是继承的替代方案，比静态继承更灵活，可以在运行时组合多个装饰器。

结构

  • Component（组件接口）：定义对象的核心接口，被装饰者和装饰者都实现此接口。
  • ConcreteComponent（具体组件）：组件接口的具体实现，是被装饰的原始对象。
  • Decorator（装饰器基类）：实现组件接口并持有一个组件引用，将所有请求委托给被包装的组件。
  • ConcreteDecorator（具体装饰器）：在装饰器基类的基础上添加额外行为，实现具体的功能增强。

装饰器模式的核心思想是"包装"：每个装饰器包裹一个组件（或另一个装饰器），调用时先执行自己的逻辑，再委托给被包裹的对象，形成链式结构。

UML 类图（文本描述）

Component <|-- ConcreteComponent
Component <|-- Decoror
Decorator --> Component（组合/关联：持有被装饰对象的引用）
Component <|-- ConcreteDecoratorA
Component <|-- ConcreteDecoratorB
  • Decorator 实现 Component 接口，同时持有一个 Component 引用
  • ConcreteDecorator 继承 Decorator，在调用 super 方法前后添加自己的行为
  • 客户端可以层层嵌套装饰器，形成装饰链

代码实现（C++ 示例）

#include <iostream>
#include <string>

// ========== 组件接口 ==========
class IDataSource {
public:
    virtual ~IDataSource() = default;
    virtual void writeData(const std::string& data) = 0;
    virtual std::string readData() const = 0;
};

// ========== 具体组件 ==========
class FileDataSource : public IDataSource {
private:
    std::string data_;
public:
    void writeData(const std::string& data) override {
        data_ = data;
        std::cout << "[FileDataSource] 写入数据: " << data << std::endl;
    }
    std::string readData() const override {
        std::cout << "[FileDataSource] 读取数据" << std::endl;
        return data_;
    }
};

// ========== 装饰器基类 ==========
class DataSourceDecorator : public IDataSource {
protected:
    IDataSource* wrappee_;
public:
    explicit DataSourceDecorator(IDataSource* source) : wrappee_(source) {}
    virtual ~DataSourceDecorator() = default;

    void writeData(const std::string& data) override {
        wrappee_->writeData(data);
    }
    std::string readData() const override {
        return wrappee_->readData();
    }
};

// ========== 具体装饰器：压缩 ==========
class CompressionDecorator : public DataSourceDecorator {
public:
    using DataSourceDecorator::DataSourceDecorator;

    void writeData(const std::string& data) override {
        std::string compressed = "[COMPRESSED:" + data + "]";
        std::cout << "[CompressionDecorator] 压缩数据" << std::endl;
        DataSourceDecorator::writeData(compressed);
    }
    std::string readData() const override {
        std::string data = DataSourceDecorator::readData();
        std::cout << "[CompressionDecorator] 解压数据" << std::endl;
        // 简化处理：去掉标记
        if (data.find("[COMPRESSED:") == 0) {
            data = data.substr(12, data.size() - 13);
        }
        return data;
    }
};

// ========== 具体装饰器：加密 ==========
class EncryptionDecorator : public DataSourceDecorator {
public:
    using DataSourceDecorator::DataSourceDecorator;

    void writeData(const std::string& data) override {
        std::string encrypted = "[ENCRYPTED:" + data + "]";
        std::cout << "[EncryptionDecorator] 加密数据" << std::endl;
        DataSourceDecorator::writeData(encrypted);
    }
    std::string readData() const override {
        std::string data = DataSourceDecorator::readData();
        std::cout << "[EncryptionDecorator] 解密数据" << std::endl;
        if (data.find("[ENCRYPTED:") == 0) {
            data = data.substr(11, data.size() - 12);
        }
        return data;
    }
};

int main() {
    FileDataSource fileSource;

    // 只使用基础数据源
    fileSource.writeData("Hello World");
    std::cout << "读取: " << fileSource.readData() << std::endl;
    std::cout << "---" << std::endl;

    // 嵌套装饰：先压缩再加密
    EncryptionDecorator encryptedSource(
        new CompressionDecorator(&fileSource)
    );
    encryptedSource.writeData("Secret Message");
    std::cout << "读取: " << encryptedSource.readData() << std::endl;

    return 0;
}

代码实现（Python 示例）

from abc import ABC, abstractmethod
from typing import Protocol


# ========== 组件接口 ==========
class Notifier(ABC):
    @abstractmethod
    def send(self, message: str) -> None:
        pass


# ========== 具体组件 ==========
class EmailNotifier(Notifier):
    def __init__(self, email: str) -> None:
        self._email = email

    def send(self, message: str) -> None:
        print(f"📧 发送邮件到 {self._email}: {message}")


# ========== 装饰器基类 ==========
class NotifierDecorator(Notifier):
    def __init__(self, wrapped: Notifier) -> None:
        self._wrapped = wrapped

    def send(self, message: str) -> None:
        self._wrapped.send(message)


# ========== 具体装饰器：短信通知 ==========
class SMSNotifierDecorator(NotifierDecorator):
    def __init__(self, wrapped: Notifier, phone: str) -> None:
        super().__init__(wrapped)
        self._phone = phone

    def send(self, message: str) -> None:
        super().send(message)
        print(f"📱 发送短信到 {self._phone}: {message}")


# ========== 具体装饰器：Slack 通知 ==========
class SlackNotifierDecorator(NotifierDecorator):
    def __init__(self, wrapped: Notifier, chat_id: str) -> None:
        super().__init__(wrapped)
        self._chat_id = chat_id

    def send(self, message: str) -> None:
        super().send(message)
        print(f"💬 发送 Slack 到 #{self._chat_id}: {message}")


# ========== 具体装饰器：Facebook 通知 ==========
class FacebookNotifierDecorator(NotifierDecorator):
    def __init__(self, wrapped: Notifier, user_id: str) -> None:
        super().__init__(wrapped)
        self._user_id = user_id

    def send(self, message: str) -> None:
        super().send(message)
        print(f"📘 发送 Facebook 消息给用户 {self._user_id}: {message}")


# ========== 具体装饰器：错误日志 ==========
class ErrorLoggingDecorator(NotifierDecorator):
    def send(self, message: str) -> None:
        try:
            super().send(message)
        except Exception as e:
            print(f"❌ [ERROR] 发送失败: {e}")


if __name__ == "__main__":
    # 基础通知
    notifier: Notifier = EmailNotifier("qiupeng@example.com")

    # 动态叠加：邮件 + 短信
    notifier = SMSNotifierDecorator(notifier, "+86-13800000000")

    # 再叠加：+ Slack
    notifier = SlackNotifierDecorator(notifier, "alerts")

    # 再叠加：+ Facebook
    notifier = FacebookNotifierDecorator(notifier, "qiupeng123")

    # 最终发送：会触发所有通道
    notifier.send("服务器 CPU 使用率超过 90%！")

    print("\n--- Python 原生装饰器语法 ---")

    # Python 也支持用 @ 语法实现装饰器模式
    def log_send(notifier_func):
        def wrapper(message):
            print(f"[LOG] 准备发送: {message}")
            notifier_func(message)
            print(f"[LOG] 发送完成")
        return wrapper

    @log_send
    def simple_notify(message):
        print(f"  → {message}")

    simple_notify("测试消息")

适用场景

  • 需要在不修改现有类的情况下动态添加职责
  • 功能组合爆炸：用继承会产生大量子类（如 Base + A + B + AB + C + AC + BC + ABC…）
  • 需要在运行时灵活地添加或移除功能
  • Java I/O 流式的链式处理场景

优点

  • 比继承更灵活：可以在运行时动态组合多个装饰器
  • 遵循开闭原则：新增装饰器无需修改现有代码
  • 单一职责：每个装饰器只关注一个功能增强
  • 避免子类爆炸：N 个功能只需 N 个装饰器类，而非 2^N 个子类

缺点

  • 对象身份问题：装饰后的对象与原始对象类型不同
  • 配置复杂：多层装饰器嵌套时，实例化和配置变得繁琐
  • 调试困难：错误追踪需要穿越多层装饰器
  • 顺序敏感：装饰器的嵌套顺序会影响最终行为

与其他模式的关系

  • 装饰器 vs 适配器：装饰器不改变接口，适配器改变接口
  • 装饰器 vs 代理：装饰器增强功能，代理控制访问
  • 装饰器 vs 策略：装饰器可以叠加多个，策略通常只选一个
  • 装饰器 vs 组合：装饰器是组合的特例，关注点在于透明地增强单个对象

实际应用

  • Java I/O：new BufferedReader(new InputStreamReader(new FileInputStream("file.txt"))) 是经典的装饰器链
  • Python：@decorator 语法本身就是装饰器模式的体现，常用于日志、缓存、权限校验
  • GUI 框架：Swing 中的 JScrollPane、JBorder 等是容器装饰器
  • Web 框架：中间件链（如 Express.js 的 app.use()）本质上是装饰器模式
  • 响应式编程：RxJava/RxJS 的操作符链（.map().filter().debounce()）是装饰器思想的体现
